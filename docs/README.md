# RACommandsPlugin

这是一个独立的 Win32 C++ 注入式 DLL 项目，逐步封装《红色警戒 2：尤里的复仇》的原生命令接入。当前版本仅面向特定的 Mental Omega `gamemd.exe` 样本：注入后验证 EXE SHA-256、解析命令符号，在游戏主帧注册原生命令，并通过原生游戏事件尝试执行任务。真实游戏注入和联机行为尚未验收。

## 构建

在 PowerShell 中运行：

```powershell
& .\scripts\build.ps1
```

当前唯一解决方案配置为 `Release|Win32`，目标为 `build\Win32\Release\RACommandsPlugin.dll`。脚本同时编译、运行纯逻辑测试。默认使用 `src/SDK/YRpp/mo-7cd005d2`；可通过 `build.ps1 -GameSdkVersion <版本目录名>` 在编译期切换 SDK。明确的游戏适配器与原生命令注册层使用 YRpp 类布局和固定地址；启动时的目标 EXE 哈希门禁阻止在其他版本执行。

## 当前运行方式

使用常规 `LoadLibrary` 注入后，DLL 会自行安排初始化，调用方不需要调用 `RACommandsPlugin_Initialize`。初始化在 `DllMain` 返回后验证 EXE 并解析 AOB，然后安装主帧 Hook；原生命令在游戏命令表就绪的主帧注册。旧的 `RACommandsPlugin_Initialize` 导出仍可手动重试；`RACommandsPlugin_IsReady` 只表示基础解析和主帧 Hook 已就绪，不表示命令、热键或联机已经通过运行时验收。

该 DLL 在安装主帧 Hook 前将自身固定到进程退出；`Shutdown` 仅停用回调并清空待发命令，不会移除原生命令、撤销 Hook 或使 `FreeLibrary` 成为安全操作。与同时 Hook `MainFrame` 的 YRHackMod 版本不支持共存，遇到已改写的入口会拒绝安装。使用前请在目标游戏环境自行验收，尤其不要将尚未验证的联机行为视为安全。

`src/NetworkEvent/` 定义目标样本的 0x6F 字节原生事件布局及按事件种类解释的 union，当前提供建筑 Produce／Place 的建构和本地玩家 OutList 适配器。适配器在目标 EXE 校验通过后绑定游戏线程；返回成功只表示事件已复制进原生 OutList，不表示事件已被执行或联机送达。布局及环形队列行为通过目标样本反汇编与离线测试核对，实际游戏与联机效果仍待验收。

「主建造栏自动续建」与「防御建造栏自动续建」各有独立热键，默认关闭；按一次开启、再按一次关闭。开启时记录对应栏位正在建造或等待放置的建筑；空栏则等待下一次手动开工，不需要 Shift。建筑完工并由玩家放置、栏位空出后，功能在类型仍可建、原生 OutList 至少有 13 个空槽时尝试发送一次原生 Produce；拥塞时保留待发状态，已入队后等待新建造出现，不盲目重复发送。`BuildLimit` 为 1–100 的建筑不纳入自动续建；未完工前换品种、取消或手动暂停会关闭对应开关。关闭或换对局会清除插件状态，已进入原生队列的事件无法撤回。当前只通过离线测试；完工后取消与正常放置都可能表现为栏位空出，真实游戏和联机行为仍需验收。

「自动为线圈充电」默认关闭；按下热键切换开关。开启时，每座本地玩家的磁暴线圈优先保持现有有效配对，再从 32 格内选择最近的空闲 SHK／SHOCK 充能兵；每个充能兵只分配给一座线圈。已分配单位被选中时会定期取消选择。关闭时撤销尚未送出的充能任务，不会强制中止已经进入游戏队列的任务。

选区命令包括筛选心控单位、按兵种／弹药／载员筛选、逐个选择单位及撤销选择。轮换筛选均以首次按键前的选中单位群为母集，后续按键会重新读取弹药、载员等实时属性；撤销保存最多 12 份完整选区快照，包含建筑物，只恢复仍存在且可选的对象。它们通过游戏原生 `Select()`／`Deselect()` 修改本地选区，不直接修改单位模拟状态。「自动修理全部建筑物」按一次开启持续修理，再按一次关闭；仅针对本方受损且可修的建筑，送出原生修理事件前保留 13 个空槽，并对同一建筑进行重试节流。

「空军分散移动」在热键按下时读取鼠标指向的地图格，将选中的飞行步兵按每格最多 3 名、飞行载具和 `AircraftClass` 按每格最多 1 个分配到附近有效格，并经共用 ClickedMission 队列尝试发送 Move。两组可使用同一格；候选格只在目标点 32 格半径内搜索，未分配的单位不下达任务。同一单位的新目标会替换尚未送出的旧 Move 意图。游戏内移动效果与联机同步仍未验证。

「IFV 同类选择」从当前选中单位提取全部 IFVMode 值，包含模式 0；第一次按键立即扩选屏幕内同模式单位，在系统双击时限内放开再按一次则扩选全场同模式单位。命令接收游戏原生 `WWKey` 的释放标志，以免把同一次长按的重复 keydown 当成第二次按键。若目标游戏未把相应释放事件分派给该命令，双击行为需要在实际注入中排查；离线编译和测试不能替代此项验收。

「A 地板模式」热键按一次开启、再按一次关闭。仅当目标 EXE 与两个原生函数入口均通过校验且双 Hook 安装成功时注册；开启后只在本地、非规划模式、按住原生 ForceFire 键进行左键强制攻击时，将这次点击对象的 Attack 主目标换成点击格。普通攻击、右键和规划模式沿用原游戏路径。原生 MegaMission 可编码 Cell 目标，但不同单位是否都能实际接受地格目标，以及真实游戏／联机效果尚未验收。

「清除所有信标」扫描最多 8×3 个已占用槽，每帧最多尝试一槽，按原游戏 Global Channel 的 61-byte 删信标命令向每个远端记录发送；所有发送调用返回非零后才具体删除本地对应槽。部分发送失败后只重试尚未被发送函数接受的远端，避免把重复删除包送给已经接受的客户端；意图到期或对局更替时清除。IDA 已确认未装插件的原版客户端能解析 owner／slot 删除命令，但原生发送函数的非零返回不保证实际写入或远端送达，因此跨客户端一致性必须在真实联机中验收，不能把离线测试当作同步保证。

「显示选中单位射程」热键按一次开启、再按一次关闭；只在目标 EXE 与 Tactical 渲染入口字节验证、Hook 安装成功后注册。它在原游戏 Tactical 渲染阶段读取选中且存活的本方载具、步兵和飞机，从当前武器的正数 `Range` 向上换算为格数，再调用游戏原生射程圈绘制器，未自建渲染器。这个圆圈仅表示当前武器的静态射程，不涵盖目标类别限制、武器自动切换或最小射程；颜色、空中单位高度与多渲染阶段的实际画面效果仍须游戏内验收。

「自动装车」在仅选中载具时，根据选中单位之间的 Size／SizeLimit、空位和装载规则区分载具与乘客，并将车辆分配给多个可用载具。既能载人又能进入更大载具的车辆优先接收可装入自己的选中车辆；只有按热键时已实际满员，才尝试进入其他载具，不在同一轮安排尚未完成的嵌套装载。无法安排载具装载时回退到本方步兵装车。

「选中单位自动碾压」把当前选中的本方碾压载具加入持续部队；「退出自动碾压」仅取消选中载具的标记与待发任务，已经下达的移动可以走完。向已标记载具用左键手动下达移动或攻击任务，也会自动取消它的标记。当前实现每 15 帧检查半径 8 格的可见敌方步兵，在已知平坦空地／道路上规划短直线穿越路线（必要时以第 9 格作终点），多车尽量避免重复目标与同格冲突；经共用队列保留至少 13 个原生空槽后才尝试发送 Move。无法证明的地形、障碍与混合占用格会跳过。移动目标的下一格预测和非直线路线尚未实现，真实路径由游戏寻路决定；游戏内碾压效果与联机同步仍须验收。

「切换安全模式」默认关闭，只调整部分命令的执行强度。安全模式下，每次自动装车按键只为一辆载具安排装载，优先步兵进入载具，没有合适步兵配对时才安排载具互装；尚在执行的载员和载具会在后续按键中暂时排除，完成、失效或超时后释放。自动修理只考虑当前屏幕内的本方建筑；首次观察到受伤或血量再次下降后，为该建筑选择 1000–4000 毫秒的等待时间，每次主帧扫描最多尝试启动一栋建筑的维修。已启动的其他建筑可继续维修。建筑尚未进入屏幕、游戏暂停、卡顿和原生事件队列拥塞都可能使实际开始时间晚于预定时间。

「焚风步兵击杀回血」按一次热键，从当前选中的本方 HUNTR 中挑选攻击者，并从其他选中步兵中排除 HUNTR、DUPL 与 `BuildLimit=1` 的单位，再按造价和当前血量选择低损失目标。目标解除编队并取消选择一次，随后依次尝试原生 Stop 和 HUNTR Attack；攻击人数按主武器伤害除以 1.3 估算，不足一轮击杀时使用全部可用 HUNTR。目标仍存活时可再次按键继续攻击。本版尚未引入追敌／防守情境判断；友军攻击、停步顺序、击杀产云与联机同步均须在目标游戏中验收。

同时选中步兵与多个开顶载具时，自动装车会按步兵注册名分组，再将每组轮流分配到可用载具；未分配的步兵仍可进入其他选中的非开顶载具。分配会检查剩余座位、SizeLimit 与自定义装载规则；数量不足或条件不兼容时不保证固定比例。只选中步兵、只有一个开顶载具或只选中载具时，维持原有分配方式。
