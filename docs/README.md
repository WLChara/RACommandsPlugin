# RACommandsPlugin

这是一个独立的 Win32 C++ 注入式 DLL 项目，逐步封装《红色警戒 2：尤里的复仇》的原生命令接入。当前版本仅面向特定的 Mental Omega `gamemd.exe` 样本：注入后验证 EXE SHA-256、解析命令符号，在游戏主帧注册原生命令，并通过原生游戏事件尝试执行任务。真实游戏注入和联机行为尚未验收。

## 构建

在 PowerShell 中运行：

```powershell
& .\scripts\build.ps1
```

当前唯一解决方案配置为 `Release|Win32`，目标为 `build\Win32\Release\RACommandsPlugin.dll`。默认只构建 DLL，所需 SDK、第三方依赖和工程文件均随源码提供；需要安装 Visual Studio 2022 的 C++ 工具及 Windows SDK。默认使用 `src/SDK/YRpp/mo-7cd005d2`；可通过 `build.ps1 -GameSdkVersion <版本目录名>` 在编译期切换 SDK。明确的游戏适配器与原生命令注册层使用 YRpp 类布局和固定地址；启动时的目标 EXE 哈希门禁阻止在其他版本执行。

### 本机开发文件

测试工程、`src/Tests/`、测试脚本、`installer/` 及构建产物仅在本机维护，已由 `.gitignore` 排除，不是克隆仓库后的构建依赖。本机持有测试工程时可运行 `& .\scripts\build.ps1 -RunTests` 显式编译并执行纯逻辑测试。

## 当前运行方式

### 热键功能分类

ESC 热键设置按用途显示六个平级分类：

| 分类 | 功能 |
| --- | --- |
| 插件：单位选择 | 心控、兵种、弹药、载员筛选，逐个选择、撤销选择及 IFV 同类选择 |
| 插件：编队与运输 | 自动列队、拖拽矩形编队、空军分散及自动装车 |
| 插件：战斗辅助 | A 地板、加入／退出自动碾压及焚风步兵击杀回血 |
| 插件：建筑管理 | 自动修理、主建造栏续建、防御栏续建及线圈自动充电 |
| 插件：超级武器 | 自动铁幕、自动狂暴及鼠标处释放力场护盾 |
| 插件：显示与工具 | 射程显示、清除信标及安全模式 |

分类名称统一维护在 `src/Commands/CommandCategories.h`，各命令注册时引用对应静态字符串。此次仅调整分类，命令内部名及热键持久化键保持不变；更换 DLL 后重启游戏，核对六类显示与原有绑定。

### Syringe 自动装载与中途注入

将 DLL 放入 Syringe 启动游戏时扫描的工作目录，即可通过 `.syhks00` 中的零地址声明及 `SyringeHandshake` 识别装载。该声明只要求装载 DLL 和解析已有导出，不安装 Syringe 功能 Hook；插件继续使用 MinHook。握手校验当前受支持游戏的文件大小、时间戳、CRC 和磁盘 SHA-256。

Syringe 在自身进程加载 DLL 进行握手时，插件不创建初始化线程。游戏进程中的自动入口先验证 EXE，再等待原生命令表就绪后安装 MinHook，避免早于 Syringe 的统一 Hook 写入。对局中使用原有 `LoadLibrary` 注入器加载同一个 DLL 时，就绪后沿用同一初始化路径。DLL 在受识别的游戏宿主中保持进程常驻；`Shutdown` 会取消尚未完成的自动启动并停用运行时。

隔离宿主验证夹具仅保留在本机；Syringe 启动游戏、对局中途注入及与其他 DLL 共存仍需实机验收。

使用常规 `LoadLibrary` 注入后，DLL 会自行安排初始化，调用方不需要调用 `RACommandsPlugin_Initialize`。初始化在 `DllMain` 返回后验证 EXE 并解析 AOB，然后安装主帧 Hook；原生命令在游戏命令表就绪的主帧注册。旧的 `RACommandsPlugin_Initialize` 导出仍可手动重试；`RACommandsPlugin_IsReady` 只表示基础解析和主帧 Hook 已就绪，不表示命令、热键或联机已经通过运行时验收。

该 DLL 在安装主帧 Hook 前将自身固定到进程退出；`Shutdown` 仅停用回调并清空待发命令，不会移除原生命令、撤销 Hook 或使 `FreeLibrary` 成为安全操作。目标 EXE 的哈希门禁通过后，主帧 Hook 使用 MinHook 从当前入口建立跳板；已有的 x86 `E9` 跳转会被重定位，调用返回的跳板会继续既有 Hook 链。主帧接入不再要求入口保持原始指令。两层回调与原函式的链式执行可由隔离宿主验证；与回放插件的实际录制、播放及其他功能交互仍需在目标游戏验收。

若注入后 ESC 热键界面没有「插件：」开头的分类，先恢复对局运行几秒再重新打开 ESC。初始化与注册阶段写入实际载入 DLL 同目录的 `RACommandsPlugin.runtime.log`，包括构建信息、宿主和 DLL 路径、版本门禁、主帧与输入 Hook 状态、命令注册数量和热键重读结果；只在阶段或注册状态变化时记录。各帧新注册成功的命令共用一次热键重读，尚未就绪或失败的可选命令不阻塞其他命令。注入器提示成功不等于插件初始化及命令注册已经成功；更新 DLL 后须重启原游戏进程。

`src/NetworkEvent/` 定义目标样本的 0x6F 字节原生事件布局及按事件种类解释的 union，提供建筑 Produce／Place 与超武 SpecialPlace 的建构和本地玩家 OutList 适配器。适配器在目标 EXE 校验通过后绑定游戏线程；返回成功只表示事件已复制进原生 OutList，不表示事件已被执行或联机送达。布局及环形队列行为通过目标样本反汇编与离线测试核对，实际游戏与联机效果仍待验收。

「在鼠标处释放力场护盾」为一次性热键：仅在本方 `ForceShieldSpecial` 已就绪、鼠标位于有效地图格且事件队列留有余量时，提交一次 SpecialPlace。命令使用本方超武槽索引，不直接修改超武状态；实际施放及联机同步仍待游戏内验收。

「自动释放铁幕」和「自动释放狂暴」各有独立热键，默认关闭；按一次开启，再按一次关闭，对局更替时重置。铁幕只纳入选中的本方地面载具，按中心格周围 3×3 格评分；狂暴纳入选中的本方步兵与地面载具，按半径 4.2 格的圆评分。候选中心必须是有效地图格，评分等权归一化考虑覆盖的选中单位数、总造价及这些单位当前或短暂等待后能够攻击的可见敌方单位数。没有合格选中单位时保持开启并等待；成功入队后等待就绪状态变化，避免每帧重复提交。最多处理 128 个选中单位和距离最近的 128 个敌方单位；超过选中单位上限时本轮跳过。实际作用边界、目标筛选效果及联机同步均须在目标游戏中验收。

「主建造栏自动续建」与「防御建造栏自动续建」各有独立热键，默认关闭；按一次开启、再按一次关闭。开启时记录对应栏位正在建造或等待放置的建筑；空栏则等待下一次手动开工，不需要 Shift。建筑完工并由玩家放置、栏位空出后，功能在类型仍可建、原生 OutList 至少有 13 个空槽时尝试发送一次原生 Produce；拥塞时保留待发状态，已入队后等待新建造出现，不盲目重复发送。`BuildLimit` 为 1–100 的建筑不纳入自动续建；未完工前换品种、取消或手动暂停会关闭对应开关。关闭或换对局会清除插件状态，已进入原生队列的事件无法撤回。当前只通过离线测试；完工后取消与正常放置都可能表现为栏位空出，真实游戏和联机行为仍需验收。

「自动为线圈充电」默认关闭；按下热键切换开关。开启时，每座本地玩家的磁暴线圈优先保持现有有效配对，再从 32 格内选择最近的空闲 SHK／SHOCK 充能兵；每个充能兵只分配给一座线圈。已分配单位被选中时会定期取消选择。关闭时撤销尚未送出的充能任务，不会强制中止已经进入游戏队列的任务。

选区命令包括筛选心控单位、按兵种／弹药／载员筛选、逐个选择单位及撤销选择。轮换筛选均以首次按键前的选中单位群为母集，后续按键会重新读取弹药、载员等实时属性；撤销保存最多 12 份完整选区快照，包含建筑物，只恢复仍存在且可选的对象。它们通过游戏原生 `Select()`／`Deselect()` 修改本地选区，不直接修改单位模拟状态。「自动修理全部建筑物」按一次开启持续修理，再按一次关闭；仅针对本方受损且可修的建筑，送出原生修理事件前保留 13 个空槽，并对同一建筑进行重试节流。

「空军分散移动」在热键按下时读取鼠标指向的地图格，将选中的飞行步兵按每格最多 3 名、飞行载具和 `AircraftClass` 按每格最多 1 个分配到附近有效格，并经共用 ClickedMission 队列尝试发送 Move。两组可使用同一格；候选格只在目标点 32 格半径内搜索，未分配的单位不下达任务。同一单位的新目标会替换尚未送出的旧 Move 意图。游戏内移动效果与联机同步仍未验证。

「自动列队」按一次热键，以当前选中的本方可移动地面载具的平均位置为中心，确定一组紧密的方形或近方形目标格，再为每辆车分配唯一目标；桥面与桥下分别计格。数量不能填满方形时优先填内部，再留外围空位；已经在最终格里的车尽量保留原位，避免互换堵路。整队目标在本次操作中保持固定，部分车辆先到位、队友临占或原生停在旁格均不重建子队形，也不在失败四次后放弃；未到位者在队列节流下继续向原目标补位。原生队友临占按本次已分配成员授权处理，外部占用和未取证的预约位仍保守拒绝。正常移动持续进展时不重下任务，无进展才重试；到位后被原生散开也会重新补原位。选区最多 1024 个符合条件的单位，候选搜索限制在中心附近 32 格，超预算整次拒绝；操作总期限为 900 游戏帧。重按替换待发计划，原生 ClickedMission／ClickedEvent（含 Stop）新命令及自动装车／加入自动碾压热键取消相应成员，已进入原生队列的事件无法撤回。新计划会让相应载具退出持续自动碾压。只有目标样本和取消 Hook 验证成功后注册，内部名为 `RAAutoFormation`。DLL 同目录的 `RACommandsPlugin.formation.log` 记录固定目标、进度及有界拒绝样本，供游戏内问题排查。真实避碰、紧密停靠、桥头、水陆混编及联机效果仍需目标游戏验收。

「IFV 同类选择」从当前选中单位提取全部 IFVMode 值，包含模式 0；第一次按键立即扩选屏幕内同模式单位，在系统双击时限内放开再按一次则扩选全场同模式单位。命令接收游戏原生 `WWKey` 的释放标志，以免把同一次长按的重复 keydown 当成第二次按键。若目标游戏未把相应释放事件分派给该命令，双击行为需要在实际注入中排查；离线编译和测试不能替代此项验收。

「A 地板模式」热键按一次开启、再按一次关闭。仅当目标 EXE 与两个原生函数入口均通过校验且双 Hook 安装成功时注册；开启后只在本地、非规划模式、按住原生 ForceFire 键进行左键强制攻击时，将这次点击对象的 Attack 主目标换成点击格。普通攻击、右键和规划模式沿用原游戏路径。原生 MegaMission 可编码 Cell 目标，但不同单位是否都能实际接受地格目标，以及真实游戏／联机效果尚未验收。

「清除所有信标」扫描最多 8×3 个已占用槽，每帧最多尝试一槽，按原游戏 Global Channel 的 61-byte 删信标命令向每个远端记录发送；所有发送调用返回非零后才具体删除本地对应槽。部分发送失败后只重试尚未被发送函数接受的远端，避免把重复删除包送给已经接受的客户端；意图到期或对局更替时清除。IDA 已确认未装插件的原版客户端能解析 owner／slot 删除命令，但原生发送函数的非零返回不保证实际写入或远端送达，因此跨客户端一致性必须在真实联机中验收，不能把离线测试当作同步保证。

「显示选中单位射程」热键按一次开启、再按一次关闭；只在目标 EXE 与 Tactical 渲染入口字节验证、Hook 安装成功后注册。它在原游戏 Tactical 渲染阶段读取选中且存活的本方载具、步兵和飞机，从当前武器的正数 `Range` 向上换算为格数，再调用游戏原生射程圈绘制器，未自建渲染器。这个圆圈仅表示当前武器的静态射程，不涵盖目标类别限制、武器自动切换或最小射程；颜色、空中单位高度与多渲染阶段的实际画面效果仍须游戏内验收。

「自动装车」在仅选中载具时，根据选中单位之间的 Size／SizeLimit、空位和装载规则区分载具与乘客，并将车辆分配给多个可用载具。既能载人又能进入更大载具的车辆优先接收可装入自己的选中车辆；只有按热键时已实际满员，才尝试进入其他载具，不在同一轮安排尚未完成的嵌套装载。无法安排载具装载时回退到本方步兵装车。

「选中单位自动碾压」把当前选中的本方碾压载具加入持续部队；「退出自动碾压」仅取消选中载具的标记与待发任务，已经下达的移动可以走完。向已标记载具用左键手动下达移动或攻击任务，也会自动取消它的标记。上桥、暂时停用等状态会暂停下令，不会删除标记。当前实现每 15 帧检查半径 8 格的可见敌方步兵，在地图有效格上规划短直线路线；优先穿过敌兵，后方无可用空格时可将敌兵格作为 Move 终点。多车尽量避免重复目标与同格冲突；经共用队列保留至少 13 个原生空槽后才尝试发送 Move。地图格的坡度、高度、普通覆盖物与空白雾区不再预先否决路线；墙、不可碾压的占用者或混合占用格仍会阻断候选。游戏原生寻路可能改道，Move 指向敌兵格也不保证成功碾压。移动目标的下一格预测和非直线路线尚未实现；游戏内效果与联机同步仍须验收。

「切换安全模式」默认关闭，只调整部分命令的执行强度。安全模式下，每次自动装车按键只为一辆载具安排装载，优先步兵进入载具，没有合适步兵配对时才安排载具互装；尚在执行的载员和载具会在后续按键中暂时排除，完成、失效或超时后释放。自动修理只考虑当前屏幕内受损且可维修的本方建筑；每批第一栋等待 1000–2000 毫秒，后续两次维修调用之间等待 100–1000 毫秒，每次主帧扫描最多发起一次维修调用。继续受伤不重置等待时间；屏幕内没有待维修建筑、关闭功能或切换安全模式后，下一批重新使用首栋延迟。已启动的其他建筑可继续维修。游戏暂停、卡顿和原生事件队列拥塞可能使实际开始时间晚于预定时间。

「焚风步兵击杀回血」按一次热键，从当前选中的本方 HUNTR 中挑选攻击者，并从其他选中步兵中排除 HUNTR、DUPL 与 `BuildLimit=1` 的单位，再按造价和当前血量选择低损失目标。目标解除编队并取消选择一次，随后依次尝试原生 Stop 和 HUNTR Attack；攻击人数按主武器伤害除以 1.3 估算，不足一轮击杀时使用全部可用 HUNTR。目标仍存活时可再次按键继续攻击。本版尚未引入追敌／防守情境判断；友军攻击、停步顺序、击杀产云与联机同步均须在目标游戏中验收。

同时选中步兵与多个开顶载具时，自动装车会按步兵注册名分组，再将每组轮流分配到可用载具；未分配的步兵仍可进入其他选中的非开顶载具。分配会检查剩余座位、SizeLimit 与自定义装载规则；数量不足或条件不兼容时不保证固定比例。只选中步兵、只有一个开顶载具或只选中载具时，维持原有分配方式。

### 对局内 HUD

支持版本的对局就绪后，插件尝试启用三项本机界面功能；可在 ESC 热键设置的“插件：显示与工具”分类绑定“显示信标箭头”“雷达消息侧显”“左下角聊天栏”分别切换。某项原生入口验证失败时会记录诊断，不放宽游戏版本门禁。

- 队友信标使用屏幕边缘的无柄方向箭头提示，按玩家颜色区分，默认显示 8 秒。只接受原生可显示的有效盟友，排除本方；删除、槽位替换、联盟变化和换对局会更新提示。箭头使用信标真实 XYZ 投影，不调用随机子格选择。
- 雷达侧栏开启后常驻，没有记录时显示“雷达事件 · 暂无事件”；展开聊天历史也会保留侧栏空间。它保留独立的本局事件历史，合并短时间内同类附近事件，并优先保留重要、未读或固定的事件。左键点击事件定位，点击右侧固定标记或右键点击事件切换固定；鼠标滚轮翻看更多事件。跳转不改写空格键的原生最近事件记录。事件过期只结束原生小地图动画，不立即删除侧栏历史。
- 左下角聊天按 `<玩家名> 消息` 显示，黑色背景为 75% 透明、文字保持清晰。未输入时新消息停留后淡出；打开聊天输入后可滚动查看历史。展开时每条消息右下角有复制图标；点击复制完整消息。输入支持光标、选择、Ctrl+A、Ctrl+C 和 Ctrl+V，粘贴不会自动发送。沿用原生对局聊天的收件对象规则，系统通知继续显示在左上角；不接管大厅和特殊线上私信。
- 战役和遭遇战允许本机输入聊天，只加入本局历史，不调用联网发送。关闭“左下角聊天栏”后恢复原生聊天；因原生单机限制，关闭此功能后不再提供单机聊天输入。
- 输入时按 ↑／↓ 召回自己提交过的内容，再按 Enter 发送；包括私聊和命令，不包括其他玩家的消息。首次向上前保存未发草稿，向下翻过最新记录会还原草稿。最多保留 100 条，连续重复内容只记一次，换局清空；中文候选期间方向键交给输入法。

聊天栏启用时，按 `/` 会直接打开输入框并填入一个 `/`。以斜杠开头的内容由本地 ChatCommand 处理；按 Enter 后关闭输入栏，结果或错误显示在本地聊天历史，可按 ↑ 召回修改。未知命令和参数错误不会作为聊天发送。

| 命令 | 用法与效果 |
| --- | --- |
| `/ignore <目标>` | 屏蔽匹配玩家之后发来的聊天及私聊；重复执行不取消屏蔽，不屏蔽自己，也不隐藏信标和战斗通知。换局后清空。 |
| `/msg <目标> <消息>` | 单次私聊，必须只匹配一名玩家且包含正文；不会改变下一条普通聊天的接收方式。可向自己发送本地消息。 |
| `/selfmask` | 切换本机聊天姓名遮罩，默认 `Player`；使用 `/setmask` 设置后沿用自定义名称。历史与消息复制同时使用遮罩，其他玩家仍收到真实名称。只影响聊天栏，不隐藏计分板等其他界面的身份。换局后关闭并恢复默认名称。 |
| `/setmask <名称>` | 设置并立即启用本机遮罩，支持中文及空格，例如 `/setmask 中文玩家` 或 `/setmask "中文 玩家"`。最多 32 个 UTF-16 单元，不接受空白名、控制符、换行或 `<`、`>`。不改变联网发送的真实姓名。 |
| `/speed <1..6>` | 1 为命令支持的最慢档，6 为最快档。战役／遭遇战修改活动速度；联机排入原生同步调速事件，失败原因显示在本地历史，可按 ↑ 重试。锁速战役不可修改。 |

目标可以使用玩家编号（本局 House 索引加 1，从 1 开始）、精确姓名或以下选择器。含空格、纯数字或以 `@` 开头的姓名用双引号包围，例如 `/msg "Player One" 你好`。目标只包含本局人类玩家，不包括 AI。

| 选择器 | 对象 |
| --- | --- |
| `@a` | 所有人，包含自己 |
| `@s` | 自己 |
| `@r` | 随机一人，可能选中自己；使用独立于游戏模拟的随机源 |
| `@e` | 当前敌人，不含自己 |
| `@f` | 当前友军，不含自己 |

例如 `/ignore @e` 屏蔽当前敌人的聊天，`/msg @r 你好` 向随机玩家单次私聊，`/speed 6` 请求最快速度。`/msg @a` 或 `/msg @f` 匹配多人时会拒绝发送。接收者失效、名称歧义或原生定向发送路径无法验证时，私聊会失败，不会转为广播。联网私聊的正文暂不支持以斜杠命令开头，避免触发原生线上命令解析。

原生聊天包的名称与颜色必须能唯一对应本局玩家才会应用屏蔽；无法识别的消息保留显示，避免误屏蔽。速度 1～6 映射内部值 5～0；原生滑块额外的更慢档 6 不在此命令范围内。

绘制和点击都使用同一套客户区／Surface 坐标换算；聊天编辑时不会把相应按键和战场点击交给移动、攻击或拖拽编队。HUD 在原生鼠标背景恢复后清理旧像素，再于通知绘制后、工具提示和鼠标绘制前合成，避免半透明背景叠黑或留下消息残影。表面持续失效时回退原生聊天。

HUD 按实际绘制区域备份背景，文字宽度与换行按内容、字体及布局缓存。IME 候选窗口仅在位置或输入法状态变化时重新设置。信标放置事件即时处理，删除及关系变化每 100ms 校对一次。

`src/UI/` 拥有历史、编辑、布局和绘制状态；原生 ABI、入口验证与 Hook 分别位于 `src/Game/`、`src/Game/TargetProfiles/` 和 `src/Hooks/`。本机纯测试覆盖编辑、历史、事件保留、像素恢复和实际 x86 桥接／文本调用 ABI。

编译、纯逻辑与原生入口核对属于离线验证。实际对局的渲染兼容、中文输入法候选窗、双端聊天、盟友信标、雷达定位及联机行为仍须游戏内验收。

## 参与开发

### 原生选区容量

插件在游戏线程首次进入就绪对局时，将原生 500 条战术候选表迁移至 DLL 常驻的 4096 条表，同步校验和更新 14 处容量、地址及扫描尾部操作数。中途注入会复制原表已有的有效候选；原有选中集合保持有效。联机与回放使用固定容量，战役和遭遇战可以在候选表满时按需增长；容量受 x86 内存和原生有符号索引范围约束。候选条目数不一定等于选中单位数。

动态扩容只在原生读取者退出后切换表；换对局重置在安全点完成，停用时保留仍被游戏引用的缓冲区。固定表或动态 Hook 不兼容时，日志分别报告可用能力，不阻止其他原生命令注册。本机隔离 Win32 宿主验证目标 PE 指令页、操作数、增长、网关寄存器、生命周期与已有入口跳转；真实框选和联机仍需游戏内验收。各功能自身的规划预算独立于原生选区容量。

### 单机与联机批量命令

普通移动、攻击及停止、散开、部署、引爆和出售事件由共享传输后端完整暂存，突破一次操作受原生 OutList 128 槽限制的问题；两层待发队列各有 65536 条保护容量。原生 OutList 及远端事件处理器保持原有布局，完整大队分帧提交，不要求所有成员在同一帧开始移动。

战役与遭遇战在原生帧解析前将待发事件写入 DoList，计入已有原生事件后，每家每帧的 MegaMission 不超过 256；原生处理与回放入口继续沿既有 Hook 链执行。LAN 和 Internet 的模式 2 使用原版压缩 FrameInfo，额外批次按发送者、目标执行帧、CRC 和计数建构，并以相同事件自回流 DoList；每个执行帧最多额外 128 条，重复窗口或时序变化保留剩余 FIFO。模式 0／1 及需要退化的窗口使用原生 OutList 分帧后端，并保留原生余量。

人工新命令会清除该单位尚未提交的旧传输记录；插件按 producer 和对局代次取消自己的任务，已进入 DoList 或已交给发送接口的记录不能撤回。编队观察将传输等待计为 Queued，避免拥塞时重复发送。规划模式沿用原生规则，回放和观战不接管新命令。运行日志汇总待发、入列、取消与故障；本机隔离验证覆盖队列及命令入口与容量接管的组合，不表示真实联机送达、未修改对端或 OOS 已验收。

### 拖拽矩形编队 Demo

在 ESC 的热键设置中绑定「拖拽矩形编队（演示）」；选中本方步兵或载具后按一次热键，进入一次性的专用编队模式。该模式接管左右键；同时按住左、右键，以第二个键按下时的位置为中心 A，持续拖动超过 0.5 秒后显示预览。松开任一键执行并退出模式；Esc、再次按热键、失去焦点或换对局取消。短于 0.5 秒的双键按压不下令，可以重试。选中身份、类别及当前陆空层在开启模式时固定，单位正在移动也可参与。Aircraft 类单位不纳入控制。

鼠标取点以原生地形命中格为准，并按该格的实际地形／桥面高度与原生投影基反算连续 XY，避免将 `ProcessClickCoords` 的 Z=0 平面坐标当作地面点。坡道最多进行四次高度修正，最终回投误差不得超过一像素；无法收敛或跨出命中格时退回该格中心。采集和预览共用高度规则。热键只开启模式，0.5 秒只控制预览门槛；起点固定在第二键按下时，不随鼠标后续移动更新。按下诊断 `drag-pointer-down` 记录事件像素、Win32 光标像素、视窗范围和回投误差。

拖动方向是纵轴，拖动长度限制横轴宽度；每排及最后不足的一排分别居中，行中心按整个矩形包络居中。金色十字表示中心，青色十字表示理想槽位，蓝线表示宽度及拖动方向。Demo 最多处理 1024 个单位，格心节距采用半径 0.4 格、边缘间距 0.3 格的演示参数（并非读取游戏的真实碰撞半径）；拖动少于 0.25 格不执行。每个陆空／桥层资源分别以「载具数＋向上取整的步兵数÷3」计算所需物理格，预览仍为每个单位显示一个点。

松键时检查每个理想物理格附近的候选格，在 1.5 格范围内投影，并同时分配竞争同层格子的载具与步兵；每格载具独占或最多三名步兵，陆空同坐标可以分别占用，桥上与桥下也分资源。非本组占用者消耗容量或阻挡目标；外部步兵留下的容量不足三人时，可退到每格两人或一人并增加行数。沿用自动列队的固定目标、重试、超时与人工下令取消；类别或陆空层变化时移除该单位的旧目标，不重新占用另一层。格点投影可能使旋转矩形产生小幅错位；预览尚不表示可占格，也不保证没有交叉路径。无法为整组找到位置或超出预算时整次拒绝，不静默执行部分队伍。

原有「自动列队」也支持相同类别与陆空容量规则，最多处理 1024 个单位；小规模全地面载具仍走既有紧凑规划，混编按物理格需求计算近方形布局。部分分配时优先实际单位数，再比较占格数和紧凑程度。两种编队共用功能目录内的纯容量规划及执行器，没有将专用算法放入 Core。

超过 256 人的大队采用按陆空／桥层分解的稀疏完整匹配，任一成员缺少合法位置则整队拒绝；小规模保留原有规划。大队以完整队形、容量和局部移动偏好为目标，不求全局最小移动距离。原生采集依据实际近方形或旋转矩形的物理槽位分散查询，同一快照按单位去重候选；降容时保留较紧凑的候选，再补充每格两人或一人的足迹。每个单位在同帧重试中最多 256 次端点查询，整帧最多 262144 次。复杂地形可因局部候选图不完整或预算不足拒绝；纯测试的 1000 人耗时不代表真实游戏帧率。

步兵席位 0–2 只是插件逻辑预约，不是原生子位置编号；下令仍用原生 Move 的地图格，不写单位坐标或占用位。地面步兵由原生 Walk 选择格内位置。空中 Jumpjet 会把目标修正到格中心或附近格，且有自己的占用冲突处理；每格三名空中步兵是规划上限，尚不能保证三名稳定对应预览内的独立位置。空中到位使用目标格与原生 `Is_Moving_Now`，不把普通悬停当作持续移动；多人同格和悬停效果仍需实机确认。

专属几何、手势状态与游戏适配位于 `src/Commands/DragFormationCommand/`；纯服务通过值型端口调用游戏，SDK、窗口捕获和绘制分别留在适配器及 Hook 内。Bootstrap 组合现有列队执行器和共用渲染入口，没有新增主帧 Hook 或移动队列。Win32 Release 与纯测试属于离线验证；实际注入后的双键输入、预览、抵达效果及联机 OOS 仍需游戏内验收。

新增或修改原生命令前，请阅读 [项目开发 Skill](../skill/ra-commands-development/SKILL.md)；新增命令的具体接入点与验证清单在该 Skill 的参考文档中。`& .\scripts\build.ps1` 构建 DLL；本机持有测试工程时用 `-RunTests` 执行测试。通过离线测试不等于通过真实游戏或联机验收。
